# Data model: first slice

Status: approved 2026-11-14.

This covers only the records the first slice needs: User, Role, Client
Organization, Contact, Opportunity, Project and Activity Event. Proposals,
invoices, time entries, tasks, notes and files come in later releases and are
not modelled here.

## Conventions

- **Ids** are random text ids generated by HQ, never reused.
- **Times** are UTC, stored as ISO 8601 text with exactly three decimal
  places, so they all have the same width. **Dates** with no time (a
  follow-up date) are stored as `YYYY-MM-DD`.
- **Domain code uses `Temporal`**: `Temporal.Instant` for times and
  `Temporal.PlainDate` for dates. It never uses `Date`.
- **The business time zone is `America/New_York`.** "Due today" and business
  days are worked out in that zone, not the server's.
- **Money** is an integer count of minor units (cents) plus a currency code.
  The currency is `USD` for now.
- **Nothing in the slice is deleted.** A client becomes `former`, an
  opportunity becomes `lost`, a project becomes `cancelled`.
- Every table has `created_at` and `updated_at`, except Activity Event, which
  has only `occurred_at`.
- Every change goes through a versioned migration.

## How the records relate

```
Role ──< UserRole >── User
                       │ owns
Client Organization ──< Contact
        │
        └──< Opportunity ──(0 or 1)── Project
                 │                        │
                 └── primary Contact      └── same Client Organization

Activity Event ── points at any one record, written by one User
```

## User

A person who signs in to HQ. Passwords, sessions and invites are held by the
kit's `staff` module, not in this table.

| Field | Type | Rule |

| `name` | text | Required |
| `email` | text | Required, unique, stored lower-case |

## Role

A named set of permissions. v0.1 ships three: `admin`, `manager` and `member`.

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | |
| `key` | text | `admin`, `manager` or `member`. Unique |
| `name` | text | Display name |

- **RolePermission** (`role_id`, `permission`) lists what each role may do.
  The permission keys themselves are defined in code and listed in
  `docs/authorization-matrix.md`.
- **UserRole** (`user_id`, `role_id`) gives a user a role. A user has at least
  one.
- HQ always has at least one active `admin`.

## Opportunity

One possible piece of work for one client.

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | |
| `organization_id` | id | Required |
| `contact_id` | id | Optional. Must belong to the same organization |
| `owner_id` | User id | Required |
| `title` | text | Required |
| `service` | see below | Optional at `new`, required from `consulted` |
| `stage` | `new`, `consult-booked`, `consulted`, `quoted`, `won`, `lost` | Starts `new` |
| `pricing` | `free`, `hourly`, `fixed`, `monthly`, `yearly` | Required from `quoted`, and for `won` |
| `value_minor` | integer | The quoted price: per hour, per period or in total, by `pricing`. Zero when `free` |
| `currency` | text | `USD` |
| `lead_source` | `word-of-mouth`, `phone`, `email`, `website`, `social`, `referral`, `other` | Required |
| `follow_up_on` | date | Optional. Shown on the dashboard when due |
| `summary` | text | Optional. The consult summary |
| `lost_reason` | text | Required when `lost` |
| `closed_at` | time | Set when the stage becomes `won` or `lost` |

`service` is one of: `consulting`, `landing-page`, `domain-management`,
`website`, `blog`, `social-media`, `application`, `automation`.

### Stage rules

- Stages move forward one step at a time: `new` → `consult-booked` →
  `consulted` → `quoted` → `won`.
- A `landing-page` opportunity may go from `consulted` straight to `won`.
- Any open stage may move to `lost`.
- `won` and `lost` are final. A reopened deal is a new opportunity.
- `won` requires a service, a pricing shape and a value.

## Project

Work Potomac has agreed to do. In v0.2 this is a stub. v0.3 adds phases,
milestones and tasks.

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | |
| `organization_id` | id | Required. Copied from the opportunity |
| `opportunity_id` | id | Required and unique: one project per opportunity |
| `owner_id` | User id | Required |
| `name` | text | Required |
| `kind` | `fixed` or `ongoing` | `ongoing` when the opportunity's pricing is `monthly` or `yearly`, otherwise `fixed` |
| `status` | `active`, `completed`, `cancelled` | Starts `active` |

### Project rules

- A project is created only by converting a `won` opportunity.
- An opportunity can be converted once.
- A `fixed` project ends as `completed` or `cancelled`.
- An `ongoing` project never becomes `completed`. It stays `active` until it
  is `cancelled`.

## Activity Event

The audit record. One is written for every change to any record above, and
for every sign-in.

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | |
| `occurred_at` | time | Set by the server |
| `actor_id` | User id | Empty only for actions HQ takes by itself |
| `action` | text | A fixed key, for example `opportunity.stage-changed` |
| `record_type` | text | For example `opportunity` |
| `record_id` | id | The record acted on |
| `context` | JSON | What changed, for example the old and new stage |

- **Events are read in the order they were written**, not by `occurred_at`,
  so a clock that is stepped back cannot reorder the log.
- **Append-only.** There is no code path that updates or deletes an event, and
  database triggers reject any update, delete or replace.
- **`actor_id` is not a foreign key.** The audit table must never be the
  reason a change is refused. Users are disabled, never deleted, so the id
  always resolves.
- **`action` is a dotted lower-case key** and `record_type` is one lower-case
  name.
- **A context key that names a secret is refused**, at any depth: a password,
  token, session, API key or card detail.
- **Sensitive values are referenced, never copied in.** `context` never holds
  a password, a token or a payment detail.
- The record change and its event are written in one transaction. If either
  fails, neither is saved.

### Note

A note on a client organization, an opportunity or a project.

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | |
| `record_type` | `client-organization`, `opportunity`, `project` | Required |
| `record_id` | id | The record must exist |
| `author_id` | User id | Required |
| `body` | text | Required, at most 5,000 characters |

Notes are written once. There is no edit and no delete. Reading or writing a
note needs the permission to see the record it is on.

### File

One uploaded file (decision 0002).

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | Its only address is `/files/<id>` |
| `name` | text | The name it was uploaded with, without any folder |
| `content_type` | text | Decided by HQ from the name. Never taken from the browser |
| `size_bytes` | integer | At most 25 MB |
| `sha256` | text | Of the bytes |
| `owner_type`, `owner_id` | text, id | What it is attached to, such as a deliverable |
| `organization_id` | id | The client it belongs to, if any |
| `client_visible` | yes or no | Whether that client may download it. Starts no |
| `uploaded_by` | User id | |

- Allowed types: PDF, PNG, JPEG, GIF, WebP, plain text, Markdown, CSV, zip,
  and Word, Excel and PowerPoint files. Each is checked against the file's
  first bytes. HTML, SVG and anything a browser could run are refused.
- Every download is sent as an attachment with `nosniff` and a sandboxing
  content security policy, so a file is never shown or run inside HQ.
- A file that someone may not download answers 404, the same as one that
  does not exist.

### Deliverable

Something handed to the client: a file attached to a project.

| Field | Type | Rule |
| --- | --- | --- |
| `id` | id | |
| `project_id` | id | Required |
| `title` | text | Required |
| `description` | text | Optional |
| `file_id` | id | Required. One file per deliverable |
| `status` | `draft`, `shared`, `approved`, `changes-requested` | Starts `draft` |
| `shared_at` | time | Set when shared |
| `decided_at` | time | Set when the client decides (v0.6) |
| `decision_note` | text | Required when the client asks for changes |

- Sharing makes the deliverable and its file visible to the client. Stopping
  makes it a draft again.
- An approved deliverable stays shared: it is the record of what was
  approved.
- Sharing again after "changes requested" asks the client to decide again.

### Project history

A project's history is read from the Activity Event table: every event on
the project itself, and every event whose `context` carries its `projectId`.
Each use case that touches a phase, milestone, task, deliverable, file or
note of a project puts the project's id in its event.

## Storage for the kit

The kit's `staff` module keeps its accounts and sessions through a store
adapter. That adapter uses one table, `kit_document` (`collection`, `key`,
`fields`), in the same database. No HQ code reads it directly.
